# ACP2 — verbs & configuration reference

Per-connector verb reference (roadmap A2), same section order as every other
connector. Samples are **real captures** against a loopback producer built from
the committed manifest fixture (`neuron-test` — SHPRM1 + CONVERT Hybrid).
acp2 has **no vendor emulator** (the Neuron is our own emulator), so a real
device walk replaces these once one is connected.

Wire format: [`../CLAUDE.md`](../CLAUDE.md). Verbs: `info walk tree get set
ensure watch export import diff convert discover profile diag`.

---

## 1. Transport configs

ACP2 runs **exclusively over AN2/TCP** (port 2072, AN2 proto=2) — no UDP, no
direct TCP. There is no `--transport` choice.

```
dhs consumer acp2 walk 10.41.40.195 --port 2072
dhs producer acp2 serve --manifest neuron-test.json --cache-dir . --port 2072
```

## 2. Controllers & redundancy

**Default = one connection.** Redundancy = **2+ instances** (one per
controller). A redundant Neuron is modelled in the manifest as **two tcp
endpoints** (ADR-0023); the manifest validator requires tcp on every endpoint
(udp is acp1-only and invalid for a redundant pair). See
[`../testdata/integration-test/manifest/neuron-test.json`](../testdata/integration-test/manifest/neuron-test.json).

## 3. Logging & severity

Logs go to **stderr**, data to **stdout** (`2>` captures logs, `1>` the result).

| Side | Flag | Values |
|---|---|---|
| consumer | `--log-level` | `trace \| debug \| info \| warn \| error \| critical` (default `info`) |
| consumer | `--verbose` | shortcut for `--log-level debug` |
| producer | `--log-level` / `--log-format` | `debug..error` / `text \| json` |

```
dhs consumer acp2 walk 10.41.40.195 --port 2072 --verbose
dhs consumer acp2 walk 10.41.40.195 --port 2072 --log-level debug 2>run.log
```


## 5. get / set (by obj-id)

acp2 addresses an object by its numeric **obj-id** (`--id`, shown in `walk`).
There is **no path-name addressing** (obj-id is the wire identifier; dotted
paths are an emberplus thing) and **no inc/dec/reset** — acp2's only mutating
method is `set_property` (get_property / set_property; see `../CLAUDE.md`).

```
$ dhs consumer acp2 get 127.0.0.1 --port 12072 --slot 0 --id 15208
value = "PSU - NPU0500-B"
raw  = 505355202d204e5055303530302d4200

$ dhs consumer acp2 set 127.0.0.1 --port 12072 --slot 0 --id 2996 --value "1.2.3"
confirmed value = "1.2.3"
raw       = 312e322e3300
```

`set` is validated against the object's metadata (kind / min / max / enum
options). An out-of-range value is rejected by the device, surfaced verbatim:

```
$ dhs consumer acp2 set ... --id 17382 --value 198        # enum idx not in options
error: acp2 error (obj-id 17382): invalid value
```

## 6. export / import

`export` → **json / yaml / csv** (`jsonl` is the raw-frame capture log, §8).
`import` applies a snapshot with `--dry-run`.

```
$ dhs consumer acp2 export 127.0.0.1 --port 12072 --slot 0 --format yaml
# acp snapshot — generated by cmd/acp
device: { ip: 127.0.0.1, protocol: acp2, num_slots: 2 }
slots: [ ... ]

$ dhs consumer acp2 export ... --format csv         # one row per object, with obj-id + OID path
ip,protocol,slot,oid,path,id,label,kind,access,value,...,max_len,...
127.0.0.1,acp2,0,,ROOT-NODE-V2.PSU.1.Type,15208,Type,string,R--,PSU - NPU0500-B,...,256,...

$ dhs consumer acp2 import 127.0.0.1 --port 12072 --file device.yaml --dry-run
```

## 8. play / watch

`watch` subscribes to announcements — acp2 requires `AN2 EnableProtocolEvents([2])`
first (the consumer does this automatically on connect). The producer can
self-drive a target with `--announce-demo`; `--capture <path>.jsonl` logs raw frames.

```
dhs producer acp2 serve --manifest neuron-test.json --cache-dir . --announce-demo --announce-demo-obj 18
dhs consumer acp2 watch 10.41.40.195 --port 2072 --capture run.jsonl
```

## 9. ensure() — idempotent converge (ADR-0007)

`ensure` converges an object to `--value`; `--check` is a dry-run. Re-running is
a no-op once converged.

```
$ dhs consumer acp2 ensure 127.0.0.1 --port 12072 --slot 0 --id 2996 --value "1.2.3"
changed=true   current="1.2.3"          # first run from a different value
$ dhs consumer acp2 ensure ... --id 2996 --value "1.2.3"
changed=false  current="1.2.3" (already converged)     # idempotent
```

## 10. Wireshark

Dissector: [`../wireshark/dhs_acpv2.lua`](../wireshark/dhs_acpv2.lua) — decodes
the AN2 frame header + ACP2 message header, every func/type/pid, per-frame Info
column (`slot | type | pid | stat`).

| OS | Plugin dir |
|---|---|
| Windows | `%APPDATA%\Wireshark\plugins\` |
| macOS / Linux | `~/.local/lib/wireshark/plugins/` |

```
#   display filter:  dhs_acpv2
#   port decode:     tcp.port == 2072
tshark -r capture.pcapng -O dhs_acpv2 -Y dhs_acpv2
```

## 11. Ansible (the exclusive integration / deploy driver — no .ps1)

acp2 has no vendor emulator, so the integration play is a self-contained
loopback: it serves the committed fixture, walks, asserts, then tears the
producer down (`ansible/playbooks/acp2-integration.yml`).

```yaml
# ansible-playbook -i inventory/hosts.ini playbooks/acp2-integration.yml \
#   -e dhs_bin=/usr/local/bin/dhs
- hosts: localhost
  connection: local
  tasks:
    - command:
        argv: ["{{ dhs_bin }}", consumer, acp2, walk, 127.0.0.1,
               --port, "{{ acp2_port }}", --log-level, debug, --slot, "0"]
      register: walk
      changed_when: false
    - assert: { that: ["'Card Name' in walk.stdout"] }
    - debug: { var: walk.stderr_lines }   # surface dhs logs (stderr)
```

dhs logs → **stderr**: `register` + `debug: var=<r>.stderr_lines` shows them;
`<r>.stdout_lines` is the data. `ansible-playbook -v` echoes task output.
