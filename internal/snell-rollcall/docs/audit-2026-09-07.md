# Snell RollCall — connector audit and Go migration architecture

Date: 2026-09-07 · Author: by-rune (agent) · Status: **proposal, no code**
Scope: `internal/snell-rollcall/assets/` (vendor SDK dump, 431 MB, 1 993 files)
Binding refs: ADR-0001 · 0002 · 0005 · 0006 · 0016 · 0020 · 0021 · 0022 ·
0023 · 0025 · root `CLAUDE.md` (spec-strict posture, scale targets, dissector rule)

This is the ADR-0025 step-1 audit for a connector that does not exist yet.
It answers four questions: what do we have, what oracle can prove it, what
does the wire actually look like (including the 16-bit / 32-bit split), and
how the C library maps onto a stdlib-only Go connector with a small
footprint and low latency.

## 0. Verdict in one screen

| Question | Answer |
| --- | --- |
| Can RollCall be implemented with **zero** external Go deps? | **Yes.** The wire protocol is fixed-layout big-endian structs over TCP with a 4-byte length prefix. K_os (RTOS shim), Rope (server menu engine) and Expat (unused) are not part of the wire. `codec/` will be stdlib-only per ADR-0006; consumer/provider need only `net`, `time`, `log/slog`, `sync/atomic`. |
| Physical device available today? | **Yes — live, verified 2026-09-07.** A full Snell RollCall software stack runs on `win11` (`10.6.250.105`): RollProxyService (IP Proxy) on **:2050**, the Centra router-controller simulator, LogServer, RollCall Control Panel 4.12.48 and TinyEmber+. A read-only probe reached **15 real RollCall units** (Centra controller + Matrix 1/2 + eight 49xx/59xx cards + XY Panel + TIELINES), **all cmdSet 12, all advertising SV_LONGSTR**. This is a live Tier 2 oracle. See the new **§2A**. A hardware Tier 3 unit is still worth acquiring, but the simulator covers the router + long-string model end to end. |
| Vendor emulator available? | **Yes, and running.** `Emulator/RouterSimulator/Router2.zip` = the Centra simulator now live on `win11`. Reference client (RollCall Control Panel 4.12.48) is also installed and connected. |
| 16-bit vs 32-bit | Two coexisting payload generations selected **per session** by the `SV_LONGSTR` (0x8000) service bit in `SP_CALL`. Detection = read `rService` from `SP_RETDEVINFO`/`SP_RETID`/`SP_IAM`. Full detail §4. |
| Size of the job | ≈22 k lines of C are protocol-bearing; ≈6–8 k lines of that is logic a Go port must reproduce. Estimated Go: codec 2.5 k, session 2 k, consumer 2 k, provider 2.5 k, dissector 1.2 k Lua, tests ≥ code. |
| Blockers | (1) `docs/ARCHITECTURE.md` gates this connector on every current connector reaching the ADR-0025 bar — **owner decision, the only real blocker left**. (2) No Tier 3 *hardware* (a live vendor stack now substitutes for development; §2A). (3) Router "Full Control" model needs the RollCall **file service**, pulling file-service messages into scope earlier than expected (§6.3). |

What this confirms against the design:

1. **Header, framing, addressing, big-endian all correct.** Every captured frame is `000c <len> <cDst6><cSrc6><rLen2> <type><flags> <payload>`; `DEVICEINFO_STR` is exactly 40 bytes; `rProtocolVersion = 3`.
2. **SV_LONGSTR is real and universal here** — every unit sets bit 0x8000. The detection rule in §4.2 is the correct path; these units want the 32-bit / long-string generation. **Coverage gap this exposes:** all 15 live units are Generation B, so the 16-bit path currently has **no live oracle** — it would be exercised only by unit tests against spec bytes. The owner is installing **a frame with slots running the 16-bit model** (2026-09-07) precisely to close this, giving both generations live: Centra = Gen B + router + P3 network shape; the frame = Gen A + P2 frame/slot shape. That pairing exercises every branch of §4.2 and both projections in §7.5A against real servers.
3. **`cmdSet 12`** is the DM key (`RollCallVersionGuideLines`): the eight card types and the two Matrix nodes are keyed `id@12`, matching the `.mnu`/`.tpl` cache names in the assets. Our DM fixtures line up with the live device.
4. **Bridge routing is exercised**: units report `rNet = 0x1000`, i.e. reached via bridge unit 0x01 ("Local RollNet"). The consumer must send `cDst.rNet = 0x1000` to address them; the proxy forwards. (Establishing a *control* session to a bridged unit still needs route-aware CALL handling — one probe CALL to `1000-08` timed out; **validate in migration Unit 5**, it is a routing detail, not a protocol gap.)
5. **Hazard §9.1 confirmed on real hardware**: every unit name carries trailing `cd cd …` uninitialised padding after the NUL (`GARBAGE=cdcd…` in the capture). The codec must truncate at NUL and zero-fill on encode.
6. The **Matrix 1 / Matrix 2** nodes carry `id=636` (`ID_ROUTER_MATRIX`) with FILE + LONGSTR, which *looked* like the Full Control Command Set router model (§6.3). **Tested 2026-09-07 and it is not.** `SP_GETVALUE` for commands **100–110 returns `SP_NACK`** on both the Centra gateway and Matrix 1, so `CMD_INTERFACE_VERSION` and the Routing Interface root are absent. The router command set therefore **cannot be validated on this oracle as configured**. Two ways to close it: set `CENTRA_SIMULATED_ROUTER` in `CentraController.bat` (the script documents Cygnus / Pyxis / Sirius800 / Vega) and re-probe, or test against a real router controller. Note `cmd 100` *does* exist on the TIELINES node, but as its own menu-driven matrix selector (20 options), not as the documented Routing Interface — do not mistake one for the other.
7. **These 15 are only the unit layer.** Each also serves `SV_PORTS`, and the real device model lives on the **ports**: `41:00` has **24** ports (`Src 1…`, id 623, **473 menu lines each**), `Matrix 1` has 2 `Router Level` ports (id 637, **5 549 lines each**), `Matrix 2` has 3. Enumeration is therefore two-level — map/net → units, `SP_GETDEVLIST` → ports, menus per port — mapping onto ADR-0022 as unit = Frame/Device and **port = Slot/Card**. A consumer that stops at unit level sees a small fraction of the plant, and the matrix/level structure is expressed by this port topology rather than by the Full Control command set. Detail in [`dm-and-ui.md` §1A](dm-and-ui.md).
8. **Writes work** (`SP_SETVALUE` → `SP_RETVALUE` with the device-confirmed value, read-back verified) and **user level does not alter the menu on this build** — same counts *and* same `HIDDEN`/`DISABLED` flags at `UL_USER`, `UL_SUPERVISOR` and `UL_FACTORY`. That is a simulator property, not a protocol one; real units do gate menus by level, so the level stays part of the DM cache key. See [`dm-and-ui.md` §5A/§5B](dm-and-ui.md).

### Direct-to-device vs proxied — the connector's primary mode

**The proxy is lab middleware, not part of the protocol.** `RollProxyService`
exists on win11 only because it was installed there. The connector must NOT
assume a proxy is in the path. Spec §10.2.4 says an IP client reaches RollCall
"via an IP Server", and lists three kinds — and the second is **the device
itself**: "an embedded unit such as an Ethernet enabled 3U IQ box". So:

| Mode | Peer | When |
| --- | --- | --- |
| **Direct** (primary) | the device's own Ethernet gateway / IPShare port | one frame, one router, one shoebox — the normal field case |
| **Proxied** (secondary) | RollProxy / RollNetIpShare / IQ Gateway | combining RollNet segments, bridging VLANs, legacy ArcNet plants |

Both are the *same* client handshake (`SP_GETDEVINFO` to `0000-00-00:FF`,
then map/ports enumeration). What differs is only **who assigns our port**:
direct, the device's gateway spoofs us onto its own unit; proxied, the proxy
does, and units then sit behind NET bridges with a non-zero `rNet` route.
The consumer therefore needs no mode switch — it discovers which it is from
the returned `SP_RETDEVINFO` and the presence of `SV_NET` bridges.

**Direct access is PROVEN on this host** (2026-09-07). Connecting straight to
Centra's own SharePort `10.6.250.105:2057`, with no proxy in the path, returns
its gateway identity and its full 15-unit map:

```
GATEWAY : 0000-08-00 id=605 cs12 MENUS|CONTROL|FILE|MAP|LONGSTR
MAP count = 15   (0000-11 Matrix 1 … 0000-81 XY Panel)
```

Note the addresses: **`0000-XX-00`, route zero**. Proxied, the same units are
`1000-XX-00` behind the "Local RollNet" bridge. That is the whole practical
difference between the two modes, and it confirms the model above — direct
means no bridge and no route to encode.

The earlier failure was **mine, not the device's**: see the root cause below.

### Incident + root cause — a malformed session index, mine

Four `APPCRASH` / `0xC0000005` faults on `CentraController.exe`, **all at the
identical fault offset `0x0099d5d8`**:

| Time | Trigger | Cause |
| --- | --- | --- |
| 00:27:26 | an **SW-P-08-framed** packet sent to Centra's port 2007 | my mistake: non-RollCall bytes on a RollCall-adjacent port |
| 00:34:40 | forwarded `SP_CALL` to a unit behind the NET bridge | **bad `rIndex`** (below) |
| 00:46:15 | same, reproduced on the direct fabric path | **bad `rIndex`** |
| 00:52:55 | plain `SP_GETDEVINFO` direct to SharePort 2057 | **bad `rIndex`** |

**Root cause: I encoded the unconnected session index as `-1` (`0xFFFF`)
instead of `UNKNOWNSESS` = 255 (`0x00FF`).** `rIndex` is declared `INT16`, so
writing "unknown" as a signed −1 looks natural and is wrong: the *value* is
255. Byte-level difference in an `SP_GETDEVINFO`:

```
WRONG  000c0011 00000000 ffff 00000000 0001 0003 1500 00
RIGHT  000c0011 00000000 00ff 00000000 0001 0003 1500 00
                         ^^^^ rIndex
```

The **proxy tolerated** the bad value and answered normally, which is why the
whole map walk succeeded and hid the defect. **Centra did not** — it almost
certainly indexes its session table with the field and faults on `0xFFFF`.
That single mistake explains all three RollCall-path crashes and the "direct
access does not work" conclusion I drew from them. With the corrected index,
direct access works first time and Centra has been stable since.

The proxy never crashed. Restored each time via a one-shot scheduled task;
the stack is **healthy** (proxy up, 2 bridges, 15 units, Centra pid stable).

What this means, separated honestly:

- **For the connector.** Our provider must never crash on malformed or
  unexpected input: fuzz the framer and every payload decoder (§7.2), bound
  every length before allocating, and reply `SP_INVCMD` / drop rather than
  fault. A shipping vendor build failing this way is the argument for the
  spec-strict absorb-and-report posture.
- **For probing this oracle.** The safe, repeatable read path is: proxy
  `SP_GETDEVINFO` → `SP_CALL{SV_MAP}` → `SP_GETLOCDEVMAP` → `SP_CALL{SV_NET}`
  on a bridge → `SP_GETLOCDEVMAP` → `SP_TERM`. That path ran cleanly many
  times. **Do not** `SP_CALL` a unit behind the bridge, and **do not** talk to
  2057 or 2007 directly, until the routing question is understood.
- **It is not a protocol finding.** A debug-build simulator faulting is a
  defect in that build. It tells us nothing about what real RollCall devices
  accept, and no compliance event should be modelled on it.
- **Resolved, not open.** The bridged-`SP_CALL` fault was the same `rIndex`
  defect, not a routing problem and not a Centra-only bug. Re-test bridged
  addressing with correct indices before assuming anything about `rNet`.
- **Lenient peers hide defects.** The proxy accepted `0xFFFF` where the device
  faulted. Our consumer must emit spec-exact values, and our provider must
  **reject** out-of-range indices rather than imitate the proxy's tolerance —
  tolerance here is what let a malformed client reach a device and crash it.
- **Operational.** Centra is hand-launched in an RDP session owned by
  `by-rune`. A headless restart via scheduled task works but attaches no
  desktop, which is fine for wire testing. Make it a service or a boot task
  before treating it as a standing oracle.

## 3. Wire model — the facts a Go design must carry

### 3.1 Transport (spec §10.2, `RC3IP.H`, `IPShClient.c`)

- TCP only. Default port **2050** (the Wireshark plug-in decodes 2050–2060). No UDP anywhere in the IP drivers; presence/discovery (`SP_IAM`) travels inside the TCP stream as a broadcast-addressed message.
- Every frame: 4-byte transmission header, then `MESSAGE_STR` (14), `ROLLHEADER_STR` (2), payload (0..420).
- **All multi-byte fields big-endian**, structs packed, no padding except the one documented pad byte in `GETNEXT_STR` (3 fields, `sizeof` 4).
- `TCP_NODELAY` mandatory for real-time control (spec §10.2.2).

```
off  size  field
 0    2    TxHdr.Flags   = 0x000C  (compat mode 3; anything else = resync)
 2    2    TxHdr.Length  = 14 + rLength          (bytes that follow)
 4    6    cDst {rNet u16, rUnit u8, rPort u8, rIndex i16}
10    6    cSrc {rNet u16, rUnit u8, rPort u8, rIndex i16}
16    2    rLength       = 2 + payload_len
18    1    rPktType      (0..71)
19    1    rPktFlags     (0x80 PF_BACKCHANNEL, 0x40 PF_WIDEAREA)
20    n    payload
```

Max frame on IP: 440 bytes (library ceiling); spec allows up to 1 574.

### 3.2 Addressing (spec §5)

`NNNN-UU-PP:SS` — `rNet` = route of up to four bridge nibbles filled from
the top; `rUnit` = node (frame / gateway / standalone unit), 0 = broadcast
or "the unit at the other end of this link", 1–15 bridges, 16–255 units;
`rPort` = module within the unit, 0 = the unit itself (IQ frame: 1–16 cards,
0xE0–0xEF Ethernet clients, 0xFF RS-422); `rIndex` = session index in the
receiving stack: 0 blind, 0xFF unconnected, 0xFE logging, 1..N sessions.

**IPShare address rewriting (library behaviour, not in the spec):** a TCP
client sends `cSrc.rNet/rUnit/rPort = 0` and the gateway stamps it as port
`0xF0 − maxConns + connId` of the gateway unit; the gateway sends
`cDst.rNet/rUnit/rPort = 0` and the client restores its own address. First
action after connect is `SP_GETDEVINFO{port 0}` to `0000:00:00:FF`; the
`SP_RETDEVINFO` reveals the gateway's real address. A Go peer that does not
implement this rewriting will be rejected by real gateways and by the
Control Panel. Mapping onto ADR-0022: **Device = rUnit, Slot = rPort, Card
identity = `ID_STR{rId, cVersion}`**, Frame = the gateway unit (port 0).

### 3.3 Sessions and channels (spec §4)

- `SP_CALL{CONNECT_STR{rService, rUserLevel, cDev}}` to `dst:FF` → `SP_ACK` with the server's `cSrc.rIndex` (or `SP_BUSY` + optional `ID_STR`, or `SP_NACK`). Service bits are all-or-nothing: any unsupported bit → whole call NACKed.
- Front channel (flag 0) client → server request/reply; back channel (flag 0x80) server → client push, **each push is itself a request the client must `SP_ACK`**. One active message in flight per channel per session; 3 s reply timeout; > 5 consecutive timeouts → session dead (library drops it without `SP_TERM`).
- Back channel is off until `SP_BKCHNREADY{1}`; control pushes additionally require `SP_REPFCHG{0xFFFF}`. On enable the server must flush every changed value (spec §9.27).
- Blind control on index 0 needs no session (answered at `UL_SUPERVISOR`, may be disabled server-side, then silently ignored).
- Implicit sessions: `SP_GETDEVLIST` / `SP_GETLOCDEVMAP` on 0xFF open a transient session closed by the last `SP_GETNEXTPKT`.
- Keepalive: **`SP_KEEPALIVE` (28) is answered with `SP_ACK` — measured live, 2026-09-07**, on both the direct device and the proxy, and on both the unconnected session (`0xFF`) and a connected session. Round trip 4 ms in all four combinations. The vendor C library never *sends* it, and its source comment ("IP Proxy responds only to `SP_GETDEVINFO` on the unknown address") is a **client-side choice, not a server limitation** — do not read it as "keepalive is unsupported". See the measured policy in §3.5A.
- `SP_TERM{TERMSESS_STR}` from either side; servers do **not** time out idle sessions — the consumer must always TERM.

### 3.4 Services (spec §7, `rService` bits)

| Bit | Service | Consumer verbs it backs | Provider must serve |
| --- | --- | --- | --- |
| 0x0001 `SV_MENUS` | menu lines (`FUNC_STR` / `MENUITEM_STR`) | `walk`, `tree`, label resolution | yes |
| 0x0002 `SV_CONTROL` | get/set/push values | `get`, `set`, `watch`, `ensure` | yes |
| 0x0004 `SV_DISPLAY` | LHS 4×20 status lines | `status` (display) | push only |
| 0x0008 `SV_FILE` | dir/open/read/write | router names files; `extract` | read path phase 1b |
| 0x0010 `SV_LOGGING` | `SP_LOGDATA` | `watch --log` (phase 2) | receive + ACK |
| 0x0040 `SV_MAP` / 0x0080 `SV_PORTS` / 0x0100 `SV_NET` | device lists | `discover`, `info`, slot enumeration | Map + Ports yes; Net no (no bridging) |
| 0x0400 `SV_TIME` | `SP_TIME` broadcast | none | optional |
| 0x8000 `SV_LONGSTR` | 32-bit / long-string generation | all of the above | **yes, both generations concurrently** |

### 3.5 Timers (library values, spec-consistent)

| Timer | Value |
| --- | --- |
| Active reply timeout | 3 s (`SP_WAIT{rWaitTime}` extends it — library never implements this; **we must**) |
| Consecutive failures → session dead | > 5 |
| `SP_IAM` period | 12.5 s + 20 ms × unit (spec: 12.5–17.5 s) |
| Map entry expiry | 60 s without `SP_IAM` |
| Transient (implicit) session GC | 60 s |
| Idle probe (`SP_KEEPALIVE`, fallback `SP_GETDEVINFO`) | 10–15 s configurable, 3 s per probe, 3 missed → reconnect (§3.5A) |
| C housekeeping tick | 500 ms (client) / 1 s (server) — **not** carried over; Go is event-driven |

### 3.5A Keepalive — measured, not inferred (2026-09-07)

Tested against the live stack, both transports, correctly-encoded frames:

| Probe | Direct to Centra `:2057` | Via RollProxy `:2050` |
| --- | --- | --- |
| `SP_KEEPALIVE` on unconnected `0xFF` | **`SP_ACK`, 4 ms** | **`SP_ACK`, 4 ms** |
| `SP_KEEPALIVE` on a connected session | **`SP_ACK`, 4 ms** | **`SP_ACK`, 4 ms** |
| Unsolicited frames during 90 s idle | **0** | **0** |
| Session alive after 90 s of total silence | **yes** | **yes** |

Four consequences for the connector:

1. **Use `SP_KEEPALIVE` (28), not `SP_GETDEVINFO`.** It is the spec's own link
   probe (§9.28), it is answered on both session kinds by both peer types, and
   it costs an empty payload against `SP_GETDEVINFO`'s 40-byte
   `DEVICEINFO_STR` reply. Keep `SP_GETDEVINFO` as the **fallback** for a peer
   that ignores type 28, and as the identity refresh it also is.
2. **Probe the session when one is open**, otherwise `0xFF`. A keepalive on
   `0xFF` proves only that the socket and the stack live; on a session it also
   proves the *session* still exists, which is what actually breaks.
3. **Liveness must be probed, never inferred.** Zero unsolicited traffic
   arrives on an idle connection, so silence carries no information. (Back
   channel was not enabled here; once it is, pushes are traffic but still not
   a heartbeat.)
4. **The probe is an active message.** It occupies the one-in-flight
   front-channel slot, so it must go through the normal send queue. Never
   inject it concurrently with a pending request, or it will be matched
   head-of-queue against the wrong reply.

Recommended defaults, aligned to the observed environment: **probe every 15 s
when idle** (matches RollProxy's own `KeepAliveInterval=15`), **3 s per probe**
(the spec's active-message timeout), **3 consecutive misses → drop and
reconnect** with exponential back-off. Stay well inside the **60 s map-expiry**
so we are never aged out of a peer's device map while still connected. Layer
stdlib TCP keepalive underneath via `transport.SocketOptions` as a second line
of defence; the C client's Treck-specific socket options silently fail on
Windows, ours will not.

Sessions surviving 90 s of silence is consistent with the C library's own
warning that units "don't time them out very well (at all), and then run out
of available sessions" — the risk is leaking sessions, not losing them, so
**always `SP_TERM`** on exit, error and context cancel.

## 4. The two generations: 16-bit vs 32-bit, and how to pick

### 4.1 What differs

| | Generation A "16-bit" (1997–2006 spec) | Generation B "32-bit / long strings" (2014 extension) |
| --- | --- | --- |
| Command number | `Command_t` u16, valid 1..0xEFFF | `ExtCommand_t` u32 |
| Menu index / count | u16 | u32 |
| Strings | ≤ 20 bytes incl. NUL, fixed 20 in `FUNC_STR`/`DISP_STR`/`TERMSESS_STR`/`ID_STR` | ≤ 64 bytes NUL-terminated, variable, UTF-8 |
| Read | 11 `SP_GETFSTAT{cmd}` → 12 `SP_RETFSTAT{FUNCSTATUS_STR(8)+tail}` | 69 `SP_GETVALUE{cmd32}` → 71 `SP_RETVALUE{VALUE_STR(12)+tail}` |
| Write | 16 `SP_SETPARAM` → 12 | 70 `SP_SETVALUE` → 71 |
| Menu count | 8 `SP_GETFUNC{base}` → 39 `SP_BLOCKHEADER` | 65 `SP_GETMENUCOUNT{base32}` → 66 `SP_RETMENUCOUNT{base,count}` |
| Menu line | 35 `SP_GETNEXTPKT{i rel. to base}` → 9 `SP_RETFUNC{FUNC_STR(58)}` (server keeps state) | 67 `SP_GETMENUITEM{abs index}` → 68 `SP_RETMENUITEM{MENUITEM_STR(22)+text\0+param\0}` (stateless) |
| Value push | 12 | 71 |
| Menu push | 9 / 30 `SP_FUNCSTYLECHG` | 68 |
| Match-ID | trailing `Id_t` after the (then fixed-20) string | inline `rMatchID` |
| Router model (§6.3) | impossible (needs > 0xEFFF commands) | required |
| Unchanged in both | header, addressing, `SP_CALL`, `SP_TERM`, `SP_BKCHNREADY`, `SP_REPFCHG` (u16 cmd even on B sessions), `SP_DISPDATA` (20 chars), `ID_STR`/`DEVICEINFO_STR`, map/port/file/log services | ← identical bytes |

### 4.2 Detection process (this is the "which version to apply" rule)

```
connect TCP :2050
  └─ SP_GETDEVINFO{0} → 0000:00:00:FF          (also keepalive later)
       └─ SP_RETDEVINFO{DEVICEINFO_STR}        learn gateway addr + rService
            │
            ├─ discover (SV_MAP / SV_PORTS lists) → one DEVICEINFO_STR per unit/port
            │        each carries its own rService  ← per-UNIT capability
            │
            └─ for the target unit/port:
                 rService & 0x8000 (SV_LONGSTR) ?
                   ├─ yes → SP_CALL{SV_MENUS|SV_CONTROL|SV_LONGSTR}
                   │          ├─ SP_ACK  → session is Generation B: use 65–71
                   │          └─ SP_NACK → compliance event
                   │                        rollcall_longstr_advertised_but_refused,
                   │                        retry SP_CALL without 0x8000 → Generation A
                   └─ no  → SP_CALL{SV_MENUS|SV_CONTROL}     → Generation A: use 8/9/11/12/16/35/39
```

Facts that shape the rule (all verified in the C source):

1. Capability is **per unit** (`rService`), negotiation is **per session** (`SP_CALL` bits). One TCP link can carry A and B sessions to different ports of the same frame at the same time.
2. There is no protocol-version handshake. `DEVICEINFO_STR.rProtocolVersion` is always 3 and is never read by anyone. `rCmdSet` is informational (menu cache key).
3. The server gates only **pushes** on the negotiated form; front-channel requests of either form are answered in the form asked. We will still **never mix forms on one session** (policy): the dissector, the replay fixtures and the compliance events stay unambiguous, and IQ gateways (which proxy module sessions) are not guaranteed to pass B-form frames for A sessions.
4. Fallback is mandatory: a unit may advertise 0x8000 and still NACK (old IQ gateway in the path). A NACK to a speculative call is absorbed, not fatal.
5. CLI: `--api-ver auto|16|32` (ADR-0002 flag). `auto` is the flow above; `16` forces Generation A even if advertised (interop with IQ module comms behind old gateways); `32` fails fast with exit 2 when the unit does not advertise it.
6. The Full Control Command Set (routers) is only reachable on Generation B sessions and additionally needs `SV_FILE` for the names files.

## 6. Data model mapping onto dhs

### 6.1 Tree / DM model (ADR-0022) — every RollCall unit

| dhs concept | RollCall source |
| --- | --- |
| Device | `rUnit` (gateway `DEVICEINFO_STR` from the probe) |
| Frame | the gateway unit; slots enumerated by `SV_PORTS` list (`SP_GETDEVLIST`) |
| Slot | `rPort` (0 = frame controller, 1..N cards, 0xE0+ Ethernet clients) |
| Card identity | `ID_STR{rId (unit type), cVersion{major,minor,alpha,cmdSet}, szUserName}` + `STATUS_STR` (present / online / local) → `SlotInfo.Identity`, `SlotStatus` (SA_PRESENT ⇒ present, absent ⇒ no_card) |
| DM (per card type) | the menu set: `FUNC_STR`/`MENUITEM_STR` lines, key `rId@cmdSet@userLevel` → `.cache/dm/rollcall/<rId>@<cmdSet>.json`; `CM_CACHEABLE` lines cache, others always re-read (spec §7.2.4) |
| Object | one menu line with a command number: label = `szText`, id = `rCommand`, kind from `CM_*` style (`CM_NUMBER/VGRAPH/HGRAPH` → KindInt with min/max/step/divScale, `CM_BUTTON` group → KindEnum, `CM_CHECKBOX` → KindBool, `CM_EDITSTRING/DISPLAY` → KindString, `CM_DATA` → KindRaw, `CM_VLEVEL/HLEVEL` → read-only Int) |
| Hierarchy | `CM_TILED`/`CM_LIST` (rStep children) and `CM_PARTIAL` (link to another partial by base index) → path segments |
| Value | `rValue` i32 + optional string + optional data, `rMode` flags; display = `printf(szParamString, rValue/rDivScale)` |
| Subscribe / announce | back channel `SP_RETFSTAT`/`SP_RETVALUE` (+ `SP_DISPDATA`, `SP_RETFUNC`/`SP_RETMENUITEM` for dynamic menus) |
| Freshness | values load stale from DM, confirmed by `GETFSTAT/GETVALUE` or a push (root CLAUDE.md rule) |

### 6.2 Manifest (ADR-0022) — from the map

`discover` = `SP_GETLOCDEVMAP` + per-unit `SP_GETDEVLIST` → one manifest
per gateway: unit address, name, type, version, services, presence. Real
`.mnu` files in the assets give us DM fixtures for hundreds of `rId@cmdSet`
pairs without a device.

### 6.3 Matrix model (ADR-0023) — routers via Full Control Command Set

A router controller is a RollCall unit whose control service exposes a
**flat 32-bit command space** with a fixed root:

- `CMD_INTERFACE_VERSION` = command **100**, `CMD_ROUTER_NAME` 101, `CMD_NUM_MATRICES` 102, `CMD_MATRIX_BASE` 103, `CMD_MATRIX_STEP` 104, `CMD_NUM_CATEGORIES` 105, `CMD_CATEGORY_BASE` 106, `CMD_CATEGORY_STEP` 107, `CMD_ASSOC_MAKE_ROUTE` 108, … (table order in the doc = command order).
- `MatrixBase(m) = CMD_MATRIX_BASE + (m−1)·CMD_MATRIX_STEP`; then per matrix `CMD_MATRIX_NAME`, `CMD_NUM_LEVELS`, `CMD_LEVEL_BASE/STEP`, `CMD_NUM_SRC/DST_ASSOCS`, names-file commands, `CMD_CONTROLLER_NUMBER`, `CMD_ASSOC_MAPPINGS`; per level `CMD_LEVEL_NAME`, `CMD_LEVEL_TYPE`, `CMD_NUM_SRCS`, `CMD_SRC_BASE/STEP`, `CMD_NUM_DSTS`, `CMD_DST_BASE/STEP`, names files; per destination `CMD_DEST_NAME_8/32/ALT`, **`CMD_DEST_ROUTED_SRC`** (Data; source pin = `matrix<<24 | level<<16 | src`), **`CMD_DEST_PROTECT_STATE`** (Numeric+String; bit 0 protect, bits 8..23 protect-id, bit 24 master), multi-channel variants.
- Values are **Data Transfer Params**: `count(u8, bit7 = string-safe)`, then items `{type u8: 1 uint-array, 2 bitmap, 3 false, 4 true, 5 uint, 6 string}` with **var-uint** (7 bits/byte, LSB first, continuation bit 7) and an optional string-safe escape (`00`→`FF FD`, `FF`→`FF FE`). This is a small self-contained codec (`codec/dtp`).
- Names come from **files** (`SV_FILE`: `SP_FILEOPEN/READ/CLOSE`) referenced by `{filename, crc}` commands; formats are fixed-width name arrays (8 / 32 chars zero-padded), 32-bit little-endian association mappings, and a documented CRC32 (poly 0x04C11DB7) sum for cache validation.
- Route result codes 0..9 (0 ok, 3 inhibited, 4 protected, 6 no tieline, 9 not connected) map to `ValidationError` / device errors in `docs/protocols/error-codes.md`.

Consequences for scale (root CLAUDE.md): the 32-bit command space places a
65 535² level at `LevelBase + dst·step`; state is `map[cmd32]` never dense
arrays; names are streamed from files, never held per crosspoint; route
tally arrives as back-channel `SP_RETVALUE` per destination (one message
per change, ≤ 440 bytes) so there is no dump to stream-decode, but the
initial tally of a 65 535-destination level is 65 535 `SP_GETVALUE`
round-trips at one-in-flight-per-session ⇒ **use several parallel control
sessions** (spec allows one session per service pair per direction; use
distinct client `cSrc.rIndex` and a second `SP_CALL` from a second
identity port) and cache aggressively. This is the same problem the 2013
design doc flags ("18k square level … longer than I am prepared to wait").

### 7.2 Codec design rules

- Fixed-size structs decode from `[]byte` with `encoding/binary.BigEndian`, no reflection, no `unsafe`. Every struct has `Size()` and a bounds check; short input → `FrameDecodeError` with offset.
- Variable tails (`FUNCSTATUS_STR` string/data/Id_t, `VALUE_STR` string/data, `MENUITEM_STR` two strings, `BUSY` optional `ID_STR`, `NACK`/`ACK` optional string) are decoded by explicit flag-driven offset arithmetic (`8 + (FS_STRING ? 20 : 0) + (FS_DATA ? rValue : 0)` for the Id_t) — never by scanning for NUL beyond the field.
- Fixed-size string fields are **truncated at the first NUL on decode**. Bytes after the NUL are **undefined by the spec**: ignore them, never compare them, never report them. Both the live Centra units and the vendor test client pad with `0xCD` (MSVC debug fill) and that is entirely compliant. We **zero-fill on encode** as our own hygiene, not as a spec requirement. Golden-frame comparison in `testdata/` must mask this padding, or fixtures become device-specific and fail against a different vendor build.
- Framer: read 4, validate `Flags == 0x000C && 1 ≤ Length ≤ 1570`, read `Length`, verify `rLength + 14 == Length`. Resync on error **by one byte** (the C library skips four, which can never re-align on an odd offset) with `rollcall_framer_resync` event. Encode ceiling 436.
- Table-driven per-type properties (from the C `MsgHandlers.c` table): broadcastable, INVSESS-able (never / always / back-channel only), valid blind reply. The session layer consults it; the dissector mirrors it.
- Command files follow the repo convention adapted to bidirectional messages: `msg_NNN_name.go` (NNN = decimal packet type, 3 digits).

### 7.3 Session core — small footprint, low delay

Design targets (measured, not aspirational, before merge):

| Metric | C library (Win32 build) | Go target |
| --- | --- | --- |
| Per link goroutines/threads | RX task + housekeeping task + TX task + 3 timer threads | 2 goroutines (reader, writer); timers via one `time.Timer` per link driven by a deadline heap |
| Housekeeping poll | 500 ms tick (client), 1 s `select` (server) | none — every transition is event-driven (`net.Conn` reads, channel sends, timer fire) |
| Per-message allocation | 512-byte refcounted buffer from a pool of 90 | 0 allocs on the hot path: `sync.Pool` of 440-byte frames, payload structs decoded into caller-owned values |
| Per server session memory | `calloc` + **1024-pointer back-channel hash (4–8 KB)** + 256-bucket address hash | ≈ 300 B struct + `map[(type,index)]` grown on demand; `map[cmd32]struct{}` for REPFCHG selection |
| Back-channel ordering | FIFO with dedup on (type,index) | same semantics, ring buffer, dedup map, bounded (configurable, default 4 096) with `rollcall_bc_queue_overflow` event |
| Latency added by the stack | ≥ 1 ms `TaskDelay` between partial sends, 10 ms on full queues, 20 ms BC retry | write path is a single `conn.Write` of one preassembled frame; `TCP_NODELAY`; target p99 stack overhead < 100 µs on loopback (bench in CI, ADR-0025 §5) |
| Active-message discipline | one in flight per session, queued locally | same; queue depth configurable; parallel sessions for bulk reads (§6.3) |
| Reconnect | immediate retry every 500 ms, no back-off | exponential back-off 250 ms → 8 s, jitter, `ObserveReconnect()` |
| Dead-link detection | GETDEVINFO probe + Treck-only TCP keepalive options | GETDEVINFO probe (period/strikes from `Deps`), plus stdlib `SetKeepAlive` via `transport.SocketOptions` |
| Global locks | one global session-table mutex held across handlers | per-link `sync.Mutex` for the session table; per-session state owned by the link's reader goroutine, no lock on the hot path; `atomic.Uint64` counters |

Dependency injection per root CLAUDE.md: `plugin.Deps{Logger, Net, Clock,
Metrics}` flows into the link; tests use an in-memory `net.Pipe` and a
fake clock to drive the 3 s / 5-strike / IAM timers deterministically.

### 7.4 Consumer (`consumer.Protocol` mapping)

| Interface method | RollCall realisation |
| --- | --- |
| `Connect(ip, port)` | dial `:2050` via `Deps.Net`, probe `SP_GETDEVINFO`, learn gateway address, start keepalive; idempotent reconnect |
| `Disconnect()` | `SP_TERM{TC_USER}` on every open session, then close |
| `GetDeviceInfo()` | gateway `DEVICEINFO_STR`: `NumSlots` from `SV_PORTS` list, `ProtocolVersion` = 3, plus RollCall-specific extras (services, generation per port) |
| `GetSlotInfo(slot)` | `SP_GETDEVINFO{port}` or the ports list entry → identity + `SA_PRESENT`/`SA_ONLINE`/`SA_LOCAL` |
| `Walk(slot)` | CALL `SV_MENUS` (plus `SV_LONGSTR`) on `unit:port`, download root partial and follow `CM_PARTIAL` links (bounded, cycle-safe), build objects + label map; DM cache by `rId@cmdSet@userLevel`; re-read non-cacheable lines every walk |
| `GetValue(req)` | resolve label/(group,id) → command; `GETFSTAT`/`GETVALUE` on the control session (walk-on-miss) |
| `SetValue(req, val)` | `SETPARAM`/`SETVALUE`; the reply carries the device-confirmed value; `SP_NACK` string → device error |
| `Subscribe(req, fn)` | ensure control session, `SP_REPFCHG{0xFFFF}` (or per-command when the unit is known to honour it), `SP_BKCHNREADY{1}`; pushes → `fn`; every push ACKed by the session layer before dispatch |
| `Unsubscribe(req)` | `SP_STOPREPFCHG` / `SP_BKCHNREADY{0}` when the last listener goes |

Verb surface (ADR-0002, verbs.md models): the **Tree/DM** set (`info walk
tree get set watch export import extract diff ensure discover status health
validate replay bench`) plus the **Matrix** set for units that answer
command 100 (`interrogate connect tally-dump protect-* usage replace names
export/import`) plus RollCall extensions: `map` (SV_MAP/SV_NET list),
`ports`, `display` (LHS lines), `menu` (raw menu dump with styles), `file
ls|get` (SV_FILE), `blind get|set` (index 0). Every dialing verb takes
`--api-ver auto|16|32`, `--user-level user|engineer|supervisor|factory`,
`--unit`, `--port` (RollCall port, distinct from `--port` TCP — name it
`--rc-port` or accept `--target 0000-20-05`).

### 7.5 Provider (gateway emulation)

- Listens on `:2050` via `transport.ListenTCP`; N connection slots (default 14 → Ethernet ports 0xE2..0xEF, matching IQ frame conventions); answers `SP_GETDEVINFO{0}` on `0000:00:00:FF` with its own `DEVICEINFO_STR`; stamps client `cSrc` per §3.2; broadcasts `SP_IAM` to every connected client on the spec cadence.
- Serves from one canonical tree (`export/canonical`): frame = port 0 with `SV_MAP|SV_PORTS|SV_MENUS|SV_CONTROL|SV_DISPLAY|SV_LONGSTR`; each slot = a port with `SV_MENUS|SV_CONTROL|SV_LONGSTR` and its own `ID_STR` from the manifest.
- Menu lines are generated from the tree (200-line partials, `RETURN` partial links, `CM_CACHEABLE` only for static lines). Both generations served concurrently; pushes follow each session's negotiated form.
- Session pool per service with `SP_BUSY{ID_STR of holder}` when exhausted, `SP_CLEARSESS` honoured, idle-session TTL (an improvement over real units, disabled by `--strict` to mimic them).
- `SetValue(path, val)` on the provider interface fires back-channel pushes to every subscribed session (`SP_RETFSTAT`/`SP_RETVALUE`) — that is what `ensure` tests and the Control Panel oracle observe.
- Router mode: when the tree carries an ADR-0023 matrix entity, expose the Full Control Command Set (command 100 root, DTP-encoded values, read-only names files via `SV_FILE`).

### 7.5A Exposing an **arbitrary DM** over RollCall (the projection)

Owner requirement (2026-09-07): the connector ships **both roles**, and the
provider must be able to publish *any* canonical DM — including trees walked
from ACP1, ACP2, Ember+ or NMOS — as a native RollCall unit, so RollCall
Control Panel / RollMap / hardware panels see it as a normal Snell device.
This is ADR-0024's **virtual frame**, with RollCall as the exposure protocol.

**Verdict: yes, and the type systems line up unusually well** — canonical
(Ember+-shaped) and RollCall come from the same broadcast-control lineage, so
`Factor` ≡ `rDivScale`, `Format` ≡ `szParamString` (both printf), and
`Minimum`/`Maximum`/`Step` map one-to-one. Four wire limits are inherent to
RollCall and must be **declared, not worked around** (spec-strict posture).

#### Projection strategies — pick per deployment

| | Shape | RollCall form | Use |
| --- | --- | --- | --- |
| **P1 single unit** | whole DM on one `rUnit:rPort` | one menu set, hierarchy via partials | one device, simplest |
| **P2 frame + ports** | ADR-0022 Frame→`rUnit`, Slot→`rPort` | port 0 offers `SV_PORTS`, `SP_GETDEVLIST` lists slots | mirror of a real chassis; matches real IQ frames |
| **P3 virtual network** | plant → many units behind a bridge | provider offers `SV_NET`; units enumerated by `SP_GETLOCDEVMAP` under a route nibble | **plant-scale virtual frame** |

P3 is not speculative: it is exactly what the live stack does (§2A). The
Centra controller publishes its 15 nodes as **separate units on RollNet
`1000` behind a NET bridge**, not as ports of one gateway. Copying that
shape makes our virtual frame indistinguishable from a real Snell network to
RollMap and the Control Panel. Default: **P2 for a mirror, P3 for a virtual
frame**.

#### Element mapping (canonical → RollCall)

| canonical | RollCall menu line (`rStyle`) | value (`rMode`) | notes |
| --- | --- | --- | --- |
| `Node` (children) | `CM_TILED` / `CM_LIST`, `rStep` = child count | — | `CM_PARTIAL` link when the subtree exceeds the 200-line partial budget |
| `Parameter` bool | `CM_CHECKBOX`, `rMinRange=1` | `FS_VALUE` 0/1 | never emit the deprecated toggle value 2 |
| `Parameter` integer | `CM_NUMBER` (+`CM_HGRAPH`/`CM_VGRAPH` when ranged) | `FS_VALUE` | `Minimum`/`Maximum`/`Step` → `rMinRange`/`rMaxRange`/`rStep` |
| `Parameter` real | `CM_NUMBER` | `FS_VALUE` (+`FS_STRING`) | `rValue = round(v × 10^d)`, `rDivScale = 10^d`; `Factor` used when present. **Lossy — see below** |
| `Parameter` string | `CM_EDITSTRING` (rw) / `CM_DISPLAY` (ro) | `FS_STRING` | 20 B Gen A / 64 B Gen B |
| `Parameter` enum (`EnumMap`) | group of `CM_BUTTON`, same `rCommand`, ordinal in `rMinRange` | `FS_VALUE` | wide enums → `CM_NUMBER` + `FS_STRING` label instead |
| `Parameter` octets | `CM_DATA` | `FS_DATA` | ≤ 408 B per message |
| `Function` | `CM_BUTTON` (action value) | `FS_VALUE` | RollCall has no invoke; the write *is* the call. Arguments need a DTP blob or a preceding parameter set |
| `Matrix` | Full Control Command Set (§6.3) | DTP | **the high-value case**: an Ember+ or SW-P-08 matrix becomes routable from RollCall XY panels; labels become the 8/32-char names files |
| `Header.Access` read-only | `CM_DISPLAY` / `CM_VLEVEL` / `CM_HLEVEL`, or `CM_DISABLED` | — | RollCall has only 4 user levels — finer ACLs cannot be expressed |
| `Header.Description` | `szText` | — | truncated to the string budget |
| `Unit` / `Format` | `szParamString` | — | direct printf carry-over |

#### Command-number allocation — stability is a correctness requirement

Command numbers are the **only** object identity RollCall has. If they move
between restarts, every client's cached view silently points at the wrong
control. Rule:

- Allocate **deterministically from the canonical tree**: sorted OID walk →
  sequential command numbers. The same tree always yields the same numbers on
  any dhs instance, so HA replicas agree without shared state.
- Persist the map (`.cache/rollcall/cmdmap/<tree-id>.json`) for auditability,
  the dissector and troubleshooting — not for correctness.
- Reserve 100..~130 when the tree carries a matrix (the Full Control root is
  fixed at 100).

#### Identity — the cache-poisoning trap

The spec guarantees that *any two units with the same `rId` + `rCmdSet` have
an identical menu set*, and real clients rely on it: the Control Panel caches
`.tpl` templates and menus keyed exactly on that pair (the `templatecache/`
and `menucache/` files in our assets are that cache). Serving two different
trees under one key makes the Control Panel render **the wrong UI**, with no
error. Therefore:

1. **Default: clear `CM_CACHEABLE` on every generated line.** Clients then
   re-read the menu on each connect. Costs connect time, cannot poison.
2. `rCmdSet` (UINT8) is a **monotonic generation counter** persisted per
   exposed profile, bumped whenever the tree-shape hash changes → clients
   invalidate correctly.
3. `rId` must **not** collide with the ~700 assigned Snell IDs in `rc3id.h`.
   Use a configured private value; request an allocation from Grass Valley if
   these units are to be cacheable in the field. → open decision §11.10.
4. Opt in to cacheable lines (`--cacheable`) only once a real `rId` is held.

#### What is genuinely lossy — declare, never fake

| Limit | Consequence | Handling |
| --- | --- | --- |
| No float on the wire (`rValue` is INT32) | reals scale by `rDivScale`; magnitude+precision beyond INT32 cannot round-trip | pick `d` from `Step`/`Factor`; fire `rollcall_float_precision_clamped`; carry the exact value in `FS_STRING` for display |
| Strings 20 B (Gen A) / 64 B (Gen B) | long labels and values truncate | truncate on a UTF-8 boundary, fire `rollcall_string_truncated`; long names only via the router names files |
| Data ≤ 408 B per message | big blobs unrepresentable as a value | expose via `SV_FILE` instead |
| Gen A command space 1..0xEFFF (61 439) | large trees overflow | require Gen B (`SV_LONGSTR`) above the ceiling, or shard across ports (P2/P3); fire `rollcall_cmdspace_exhausted`. Pre-2014 clients simply cannot see such a tree — state it, do not silently subset |
| 4 user levels | finer per-object ACLs collapse | map `Access` to the nearest level; document the collapse |
| No object IDs | identity *is* the command number | deterministic allocation above |

Round-trip: RollCall → canonical → RollCall is lossless. **Foreign protocol →
canonical → RollCall is lossy exactly at the rows above**, and the connector
reports each occurrence as a compliance event rather than quietly degrading.

#### Validation path (free, thanks to §2A)

The live stack gives an unusually strong provider test: point **RollCall
Control Panel 4.12.48** at our provider and walk/set/subscribe. If a
third-party 2014 Java client renders and drives a projected ACP2 or Ember+
tree, the projection is correct in a way no self-written test can prove.
That is migration Unit 6.

### 7.5C Producer VALIDATED against the vendor client (2026-09-07)

with one slot (`0000-20-01`) carrying a spread of data types — and **RollCall

| 101 | `NUMBER`, `divScale` 10, `"%0.1f dB"` | −346 | **−34.6 dB** + slider + preset button |

#### The blocking discovery: a template file is mandatory

**A RollCall producer cannot be rendered by the standard Control Panel from the
menu service alone.** Two failures, each precise:

1. `Failed to download the template: 0000:20:01 Failed to connect to File server NACK`
   → the client opens a **`SV_FILE`** session on the *slot*.
2. `Failed to decompress the template: Zip file contains no entries`
   → the payload must be a real ZIP.

The captured exchange gives the exact contract:

```
CALL port 01 svc=0x0008 ul=2         file service, at the session's user level
FILEOPEN  name='TEMPLATE.ZIP'        fixed filename — not derived from rId
FILEREAD  off=0 / 227 / 454          chunked reads until the declared length
FILECLOSE
```

`TEMPLATE.ZIP` is a ZIP containing a single `Template.tpl`, an INI keyed
`[rId:cmdSet:userMask:0]` that maps **GUI widgets to command numbers**:

```ini
[Version]
version=1
[9002:1:15:0]
Size=0,0,440,300
Ctl4=New Scrollbar,101,0,-9,80,80,110,8    ; slider   -> cmd 101
Ctl8= ,102,1,64,80,100,17,8                ; checkbox -> cmd 102, on-value 1
Ctl1=Card Type,-1,0,-26,10,60,60,8         ; static label
```

Widget type codes decoded from shipping vendor templates and confirmed by our
own rendering: `-100` tab/menu bar · `-26` static text · `-18` value box ·
`-9` scrollbar/slider · `-14` preset button · `64` checkbox (positive, with the
on-value in the preceding field).

**Consequences for the connector.** The file service moves from "phase 1b,
needed for router names" to a **hard requirement for client compatibility**, and
the producer must additionally *generate* a template from the canonical tree —
a second projection alongside the menu one in §7.5A, laying widgets out from
element order and kind. Both belong in migration Unit 6. Note the template is
what the earlier cache-poisoning warning is really about: it is keyed on
`rId:cmdSet`, so an invented `rId` that collides with a real product would make
the Control Panel draw the wrong panel entirely.

#### Both generations served from one producer — validated

A second slot was added that is genuinely legacy: it does **not** advertise
`SV_LONGSTR` and it NACKs the 32-bit packet types the way a pre-2014 unit
would. The Control Panel drove both correctly.

| | Slot 1 `20:01` | Slot 2 `20:02` |
| --- | --- | --- |
| Advertised | `MENUS\|CONTROL\|FILE\|LONGSTR` | `MENUS\|CONTROL\|FILE` |
| Client's `SP_CALL` | `svc=0x800B` → **32-bit** | `svc=0x000B` → **16-bit** |
| Menu | `SP_GETMENUCOUNT`/`GETMENUITEM` | `SP_GETFUNC` → `BLOCKHEADER` 13 × 58 B `FUNC_STR` |
| Values | `SP_GETVALUE`/`SETVALUE` | `SP_GETFSTAT`/`SETPARAM` |
| Same 33-char string | `Long Name Over Twenty Chars 32bit` (33) | `Long Name Over Twen` (**19**) |

Three things this proves that could not be proven from the spec alone:

1. **The client negotiates per node, from `rService`.** It requested
   `SV_LONGSTR` only on the node that advertises it — exactly the detection
   rule in §4.2, now confirmed against a real client rather than inferred.
2. **The fallback path is real.** `port 02: 32-bit type 69 on a 16-bit unit ->
   NACK` is immediately followed by `port 02: GETFUNC (16-bit menu)`. A client
   that meets a NACK on the 32-bit form drops to the 16-bit form and carries on.
3. **The 20-byte truncation is exactly as documented** — 19 characters plus a
   terminator — which is the entire reason the 2014 long-string extension exists.
4. **The two slots really are independent.** Fetching `TEMPLATE.ZIP` from each
   port over the file service returns different archives (417 vs 418 bytes,
   different SHA-256), differing in the section key `[9002:…]` vs `[9003:…]` and
   in **every** widget's command number (100-106 vs 300-306). So the file service
   serves per-port templates, and the 16-bit result is not an artefact of the
   32-bit template being reused.

Also observed: the Control Panel opened one session at `ul=0` (`UL_USER`) while
others were `ul=2` (`UL_SUPERVISOR`), so **user level varies per session even
within one client**. A provider must honour the level carried in each `SP_CALL`
and never assume one level per client.

#### Preset ("P") uses `FS_PRESET`, not `MaxRange+1`

The spec offers two ways to request a preset recall: set `FS_PRESET` (0x10) in
`rMode`, or write `MaxRange+1`. The audit previously recorded both as equally
valid. **The real client uses `FS_PRESET` exclusively**, on both generations:

```
SET 32-bit cmd=101 mode=0x0010(PRESET) sent=0 -> value=-60    *** PRESET RECALLED ***
SET 16-bit cmd=301 mode=0x0010(PRESET) sent=0 -> value=-120   *** PRESET RECALLED ***
```

Note `sent=0`: the value field is **ignored** when `FS_PRESET` is set, so a
provider must not interpret it. Implement `MaxRange+1` as an accepted alternative
for older controllers, but drive the P button from `FS_PRESET`.

#### Full contract compliance — implemented and verified

The producer was extended from "answers requests" to a **conformant server**.
Each row below was exercised against the live spike:

| Contract obligation | Source | Verified behaviour |
| --- | --- | --- |
| Back channel is an **active-message** channel: one push, wait for `SP_ACK`, then the next | §4.2, `BackChannel.c` | per-session queue with dedup on (kind, index) and an `awaiting` gate |
| `SP_BKCHNREADY(1)` flushes current display state | §9.27 | `SP_DISPDATA` lines queued on enable |
| `SP_REPFCHG` gates value pushes; `0xFFFF` = all | §4.6.2 | catch-up burst of current values on subscribe |
| A write is pushed to **every other** subscribed session | §7.1.1 | `SETVALUE` on session B → back-channel `RETVALUE` on session A |
| Pushes follow **each session's** negotiated generation | §4.2 | `SP_RETVALUE` (71) on 32-bit sessions, `SP_RETFSTAT` (12) on 16-bit |
| Value limited to `[min,max]` and constrained to a multiple of step | §9.17 | sent −203 with step 5 → stored **−205**; sent −9999 → **−720** |
| Value beyond `rMaxRange` means "set to default" | §9.17 | sent 9999 (max 300) → **−60**, the preset |
| Binary objects accept 0, 1, or 2 = toggle | §9.17 | sent 2 twice → 1, then 0 |
| Blind control on session index 0, no session needed | §7.1.2 | `SP_GETVALUE` on index 0 answered |

| Unknown packet type → `SP_INVCMD`, not `SP_NACK` | §9.15 | type 90 → **INVCMD** |

Two simplifications remain, both deliberate and recorded rather than hidden:
the spike does **not** spoof a distinct `rPort` per client the way a real
gateway does (it routes by TCP connection instead), and it does not implement
`SP_CLEARSESS`. Neither affects the wire contract for a single-frame producer,
but both belong in the real connector.

#### Addressing bugs a real client found that our own tests could not

The Control Panel's built-in **Comms Window** (its packet monitor) exposed three
addressing faults. Each looked fine against our own consumer, because our
consumer was equally wrong or simply did not check.

| Fault | Symptom in the capture | Rule |
| --- | --- | --- |
| Reply carried `cSrc.rIndex = 0` | `Rx: 0000:20:00/**000**` on a session addressed at `/001` | On a session, the reply's `cSrc.rIndex` is **our** session index; unconnected, it is `UNKNOWNSESS` (`0FF`). Confirmed against Centra. |
| Back-channel push addressed with **our** index | `Rx: …/003 => 0000:00:00/**003**` answered by `Tx: … Type:23 **InvSess**` | The client's `cSrc.rIndex` from its `SP_CALL` is **sticky** (§5.4). Every back-channel message must use it as `cDst.rIndex`. Ours is only ever `cSrc.rIndex`. |
| Display data pushed to a map session | `SP_DISPDATA` queued on a `SV_MAP` session | `SP_DISPDATA` and value updates belong to the **control** service. Gate every push on `SV_CONTROL`. |

**All three fixed and confirmed by the client's own trace.** After the fix the
push is addressed `=> 0000:00:00/004` (the client's sticky index) from
`0000:20:00/003` (ours), and the client answers `Type:1 Ack Flags:B` instead of
`InvSess`. A full reconnect then ran with **zero protocol errors** across all
three nodes: identity, template download, menu upload, back-channel display
flush, value reads, writes and presets — on both generations.

The second is the one that matters. **Every push was silently rejected** — the
server logged "pushed to 1 session", the client replied `SP_INVSESS`, and
nothing surfaced in the UI. A back channel can therefore be *completely
non-functional while looking healthy from the server side*. Two lessons for the
connector: the provider must treat an `SP_INVSESS` answer to a push as a
**fault to report**, not as an acknowledgement to discard; and the consumer must
send `SP_INVSESS` when a push is misaddressed rather than quietly accepting it,
or it will mask this class of bug in the peer.

#### Second bug found: never answer `SP_IAM`

The Control Panel broadcasts `SP_IAM` (type 33) at roughly 1 Hz. The first
emulator replied `SP_NACK` to every one. The spec is explicit that IAM expects
**no reply**. Absorb it silently; a provider that answers will flood any client
that announces itself.

Writes also arrive as a **stream** during a slider drag (one `SP_SETVALUE` per
step, dozens per second), so the provider's write path must be cheap and must
not allocate per message.

### 7.5D Diagnostics — we need the Comms Window equivalent

Every bug found on 2026-09-07 was found by the vendor client's **Comms Window**,
its built-in packet monitor, and none by our own tests. That is not luck: it
renders a *decoded* line per frame including the addressing. All three faults
were addressing faults, which a hex-only or payload-only view cannot show.

What we already have, and why each missed them:

| Layer | Gives | Why it missed these bugs |
| --- | --- | --- |
| `--capture` JSONL (ADR-0021) | byte-exact `hex`, replayable | raw hex; decoding is manual |
| `slog` events (docs/logging.md) | semantic events, `--log-level` | application level, not per-frame |
| Wireshark dissector | full decode | out-of-band; needs tshark in the path |

**Missing tier: a live decoded frame trace in the connector's own output.**
Target format, modelled directly on the Comms Window:

```
03:07:53.361  rx  0000:20:00/003 => 0000:00:00/004  DISPDATA  flags=B   line=0 text="DHS Virtual Frame"
03:07:53.362  tx  0000:00:00/004 => 0000:20:00/003  ACK       flags=B
03:07:55.885  rx  0000:20:01/006 => 0000:00:00/008  RETVALUE  flags=-   cmd=101 mode=VALUE value=-60
```

The session indices on **both** sides of the arrow are the load-bearing part.
`=> 0000:00:00/003` versus `/004` is the entire sticky-index bug, and it is
invisible without them.

Design rule: **one decoder, three renderings, never a stored duplicate.**

- `codec.Describe(trame) string` renders one line from decoded structures.
- Emitted per frame at `--log-level debug` for live work.
- The same function renders `dhs validate frames.jsonl` in text mode, so an
  offline capture reads exactly like a live session.
- The Lua dissector's Info column uses the same field names and order, so a
  Wireshark view and a `dhs` log line agree.

Do **not** store the decode in the JSONL. ADR-0021 makes `hex` the contract and
reserves `note` for `--stop-at` scenario markers; a stored decode would drift
from the bytes and duplicate the codec (ADR-0015). Derive it on demand.

Two further payoffs. A failing codec test should print the decoded line, not a
hex diff — that is the difference between a five-minute and an hour-long debug.
And a provider must **log a rejected push as a fault**: today's server cheerfully
logged "pushed to 1 session" while the client was answering `SP_INVSESS` to
every one. Any push answered by something other than `SP_ACK` is an error and
must be surfaced, not counted as delivered.

This generalises beyond RollCall and is worth raising for every connector.

| `TX` flag stored per record | Tx / Rx Packets checkboxes |
| `LiveMode` | the scrolling live view |

Five design decisions worth adopting verbatim:

1. **Filter at record time, not at display time.** `RecordMessage()` tests both
   filters before storing anything, so a disabled trace costs one array lookup
   per frame and bounded memory. Ours must be equally cheap on the hot path.
2. **Ring buffer plus trigger.** Capture runs continuously into
   `MsgBuffer[SizeOfMsgStore]` (`MsgTraceSize` configurable, saturating count);
   `trig` freezes it, `dump`/`list` reviews it. This is a **flight recorder**,
   and it is how you catch an intermittent fault you cannot predict. Nobody
   runs `--log-level debug` permanently in a plant.
3. **Live mode is a toggle on the same recorder**, not a second path —
   `PrintMessage()` renders both the live line and the post-hoc dump, so the two
   can never disagree. That is the "one decoder, three renderings" rule the
   vendor already follows.
4. **Two filter axes: packet type and address.** Exactly the right axes here,
   and they generalise to any connector as type plus peer.
5. **Record which physical interface the frame crossed.** With several links,
   direction alone is not enough to place a frame.

Concrete proposal for the connector:

| Need | Mechanism |
| --- | --- |
| byte-exact replay | `--capture` JSONL (ADR-0021), unchanged |
| live follow | `--log-level debug`, one decoded line per frame |
| noise control | `--trace-type <list>` and `--trace-peer <list>`, applied **before** recording |
| intermittent faults | in-memory ring of the last N trames, **dumped automatically on a fault** (decode error, `SP_INVSESS`, timeout, NAK) |

The flight-recorder row is the one that would have paid for itself today: the
rejected-push bug produced no error output at all, and a ring dumped on the
first `SP_INVSESS` would have shown the misaddressed frame immediately.

#### Fit with the existing syslog contract — no new flag family

[`docs/logging.md`](../../../docs/logging.md) (epic #987) already mandates what
was asked for: **RFC 5424 syslog by default**, and a local file that is already
**per connector, per host and per verb** at
`.cache/logs/<proto>/<host>/<verb>.log`, with `--log-format`, `--log`,
`--syslog-addr` and `--log-level`. RollCall inherits all four unchanged; the
wire trace must fit **inside** that contract, not beside it (ADR-0015).

The one real tension is rate. We measured the Control Panel emitting roughly
**60 `SP_SETPARAM` per second from a single slider drag**. A plant running the
port plan's ten-plus producers would push tens of thousands of frames per
second. Forwarding that to a syslog server would swamp it, which is why
`--syslog-addr` already counts dropped datagrams.

Resolution — two planes, one contract:

| Plane | Content | Level | Local file | `--syslog-addr` |
| --- | --- | --- | --- | --- |
| **Operational** | connect, session open/close, compliance events, faults, value changes when subscribed | info / warn / error | yes | **yes** |
| **Wire trace** | one decoded line per frame | **debug** | yes | **no — capped at info** |

Three rules follow:

1. **The remote sink caps at info.** A debug session must never reach the NOC;
   one engineer debugging would otherwise drown the collector.
2. **The decoded line stays RFC 5424**, not free text: structured data carries
   the fields (`dir`, `src`, `dst`, `type`, `flags`, `cmd`) and MSG carries the
   human rendering. Loki and a terminal then read the same record.
3. **A fault escalates a bounded summary, not the firehose.** When the flight
   recorder trips, emit **one** warn/error event holding the last N decoded
   frames, or the path to the dumped file. The NOC gets the evidence; the
   frames stay local.

That third rule is the reconciliation the owner asked for: syslog everywhere,
per-connector files everywhere, and the high-rate detail available without ever
being shipped by default.

### 7.5E The vendor Wireshark dissector — our naming reference

`assets/Tools/Wireshark/rollcall.dll` (51 712 bytes, plugin v1.0.2, built for
Wireshark **1.10.5 win32 only**) is Snell's own dissector. Its full vocabulary
was recovered by string extraction into
[`captures/vendor-dissector-fields.txt`](captures/vendor-dissector-fields.txt):
**72 packet-type names and 163 field abbrevs**, plus its tree labels.

**Decision: keep the vendor's suffixes, change only the prefix.** Root
CLAUDE.md requires a `dhs_` prefix so we never collide with a namespace a
built-in or the vendor plug-in may already own:

```
rollcall.msg_flags.backchan   ->   dhs_snell_rollcall.msg_flags.backchan
rollcall.menuitem_str.rstyle  ->   dhs_snell_rollcall.menuitem_str.rstyle
rollcall.services_flags.longstr -> dhs_snell_rollcall.services_flags.longstr
```

Two reasons this matters more than it looks. Every Snell-trained engineer
already knows these filter names, so display filters translate by a single
prefix substitution. And it forces our field set to be *at least* as complete
as theirs, because a missing suffix is immediately visible as a gap.

**We must be a strict superset, and that is checkable.** The vendor's own guide
admits gaps, and the binary confirms them with the literal strings
`"Payload Decode Not Available"` and `"No Payload"`:

| Vendor state | Types |
| --- | --- |
| Not decoded yet | `WAIT` · `CLEARSESS` · `FUNCSTYLECHG` · `FILERENAME` · `SETMULTI` |
| "probably never" | `REALTIME` · `SETGROUP` · `STOPGROUP` · `SETGRPFUNC` · `ROUTEERROR` · `STREAMMODE` · `STREAMDATA` · `RAW` · `SETUSERLEVEL` · `RETDISPCAPS` · `DRAWBITMAP` · `DRAWTEXT` |

Root CLAUDE.md requires **every** transport, wire version and type decoded, so
`dhs_snell_rollcall.lua` must cover all 17 the vendor skips. That is a concrete
acceptance test, not an aspiration: decode the same pcap in both and ours must
show a payload tree wherever theirs shows "Payload Decode Not Available".

**It cannot be deployed, only compared.** It is a closed win32 binary tied to
Wireshark 1.10.5, so it cannot run on the fleet's tshark (`dhs-tools` runs
current Wireshark on Linux). Its role is a **one-off cross-check oracle**: run
a golden pcap through both, diff field by field, then retire it. Ours in Lua is
what actually ships and what `ansible/playbooks/deploy-dissector.yml`
distributes.

It registers on `tcp.port` (2050-2060 per its guide). Ours registers the same
range plus a heuristic on `flags == 0x000C && rLength + 14 == length`, so a
non-default port still decodes — the vendor's requires "Decode As...".

### 7.5B Can we be IPShare ourselves?

Owner question (2026-09-07): *"IPShare possible too, like installed on the
workstation?"* Three different things carry that name. They have very
different answers.

| Role | What it does | Verdict |
| --- | --- | --- |
| **IPShare server** (device side) — Centra `:2057`, an Ethernet IQ gateway | accept TCP clients, assign each an `rPort` on the host unit, answer `SP_GETDEVINFO` on `0000-00-00`, route between clients and local units | **Already the producer.** Not extra scope |
| **IP Proxy / Combiner** — `RollProxyService.exe` on win11 | be an IPShare *client* to several upstreams, present their union as bridged nets (`SV_NET`), and serve TCP clients itself | **Feasible, pure Go, no new deps.** Separate deliverable |
| **RollNetIpShare** — `RollNetIpShare.exe` | bridge IP ↔ RollNet (ArcNet, COM20020 card) | **Out of scope** — proprietary hardware |

**The first is free.** Serving a DM to a RollCall client already requires
accepting TCP, stamping client addresses onto ports, answering the unconnected
`SP_GETDEVINFO`, and routing to virtual units. That *is* the IPShare server
role — §7.5 P2/P3 describe it without naming it. Building the producer builds
an IPShare server whether we call it that or not.

**The second is the interesting one**, and it is just consumer + producer
composed: N upstream client links, one downstream server, a routing table
keyed on `rNet` nibble per segment. In dhs terms it is ADR-0024 federation —
fronting one real device is a **mirror frame**, combining several (or mixing
in foreign-protocol DMs) is a **virtual network**. It would let dhs replace
`RollProxyService`, and it doubles as a capture/replay rig since every frame
crosses it.

Two prerequisites before attempting it: **bridged `rNet` routing must be
proven** (still open — the earlier failure was the `rIndex` bug, so this needs
a clean retest), and ADR-0025 ordering says the consumer and producer finish
first. Sequence it as a third deliverable, not in parallel.

Deliberately excluded: ArcNet/RollNet bridging, serial, and I2C. They need the
COM20020 hardware and add nothing to an IP-only plant.

## 9. Hazards carried from the C library (must be in `CLAUDE.md` "What NOT to do")

1. Fixed-size string fields (`szUserName[20]`, `szText[20]`, `szTermString[20]`, …) hold a NUL-terminated string; **the bytes after the NUL are undefined and must be ignored**. Live Centra units and the vendor client both leave `0xCD` there and are compliant — this is *not* a deviation, *not* a mismatch, and must never raise a compliance event. Decode to the NUL; zero-fill on encode (our hygiene); mask the padding when comparing golden frames.
2. `GETNEXT_STR` is 3 fields, 4 bytes on the wire (pad); `BLOCKHEADER_STR` has an explicit align byte at offset 1.
3. `FUNCSTATUS_STR` trailing Id_t offset depends on `rMode`; string is fixed 20 when `FS_MATCH_ID` is set, else NUL-terminated ≤ 20.
4. Never send `cSrc.rNet/rUnit/rPort` ≠ 0 on an IPShare client link; never expect `cDst` to be filled by the gateway.
5. Session index 0 = blind, 0xFE = logging, **0xFF = unknown**; `rIndex` is a **signed** 16-bit field. **Trap, proven live:** because the field is `INT16`, writing "unknown" as `-1` (`0xFFFF`) instead of the value `255` (`0x00FF`) is an easy and invisible mistake — a lenient proxy answers anyway, while a real device faults on it. Encode `UNKNOWNSESS` as the literal 255, and have the provider reject any `rIndex` outside 0…255 with `SP_INVSESS` instead of indexing a table with it.
6. Address compare in real stacks ignores `rIndex` and treats `rUnit = 0` as wildcard — do not "fix" this in the provider or the Control Panel stops working.
7. Exactly one active message per channel per session; replies match head-of-queue, not command number. Do not pipeline on one session.
8. `SP_SETMULTI` has no positive reply — never wait for one; it is not usable inside the active queue.
9. Servers do not time out sessions: always `SP_TERM`; on CLI exit, on error, on context cancel.
10. `SP_REPFCHG` payload is u16 even on 32-bit sessions; most units ignore any value but `0xFFFF`.
11. `SP_KEEPALIVE` **is** honoured — by the device and by the proxy, on `0xFF` and on a session (measured, §3.5A). The C library's "probe with `SP_GETDEVINFO`" is its own choice; keep `SP_GETDEVINFO` only as a fallback for peers that ignore type 28.
12. A repeated `SP_CALL` with identical (addresses, services) tears down the existing session on the server side — reconnect logic must expect the old session to vanish.
13. `SP_WAIT` may arrive as the "reply" to an active message; it extends the timeout, it is not the answer.
14. `SV_LONGSTR` is bit 15: keep `Service_t` unsigned everywhere (the C enum is signed).
15. Menu server user-level bitmask ordering in the vendor code disagrees with the `UL_*` enum — test provider filtering against the spec, not the C table.
16. IP Proxy / IQ gateway proxies module sessions and may not pass Generation B frames to modules (2014 doc §"Packet Forwarding"): fallback path is mandatory.
17. Blind control disabled server-side ⇒ request silently dropped, not NACKed: blind verbs need a timeout-to-exit-1 path with a clear message.
18. Command numbers are meaningless without `rId@cmdSet`; never cache a menu across differing cmdSet; never hard-code command numbers outside the router root (100..).
