# CLAUDE.md — prism (Telestream PRISM waveform monitor)

**Never tested on a real PRISM.** Built and proven on a fake only; the
first real run is the customer-site runbook, [`docs/runbook.md`](docs/runbook.md).

## Authoritative spec

The page a PRISM serves at `/api/help`, saved as
`assets/PRISM API Documentation.html`. It came off a customer's
instrument and stays out of git. There is no other document.

The table renders from `GET /api/apiHelp`, a JSON the page's script
reads (`data.tags[name]` = `access`, `type`, `description`, `scope`,
`group`, `options`). No call of the table names it; the runbook brings
it back, because it holds the real scope family and option flags of
every call.

## URL

`http://<host>:9000/api/NAME[/SCOPE][?field=object.parent1.target]`.

| Family | Scopes | Calls |
|---|---|---|
| tile | tile1 .. tile8 | 114 |
| config | config0 .. config5 | 39 |
| port | IP1, IP2 | 28 |
| slot | slot0, slot1 | 2 |
| slot0 | slot0 | 1 |
| index | index1, index2 | 1 |
| index0 | index0 | 1 |
| timing | IP1, IP2, SDI1 .. SDI4, SDI1-4, EXTREF | 1 |
| input | the query `?input=0..5`, on `inputConfigure` | 1 |

The family comes from the description, then from the default scope the
script writes into the row's link. `input_status` and `tile_freeze` also
answer with no scope.

## Values

- GET answers `{"object": <value>}`. The `?field=` answer is the member
  alone, not held to the wrapper or to the datatype.
- POST sends `{"object": <value>}`: "put {...} in the request object",
  `POST {"object":{}}`. `activeInput` and `inputConfigure` take their
  JSON as it stands: "consumes a JSON object in the POST body".
- quantity is an array even with one value: `[ "5 stops"]`.

## Reads and writes held back

The list lives in `tools/gen-prism-catalogue` and ends up as flags in
the catalogue.

- **no-read** (never GET, not by walk, get or watch): `help`,
  `downloadScreenshot`, `system_reboot`, `system_poweroff`,
  `data_logger_db_diag_init`, `fan_diag`, `eye_calibration_save`,
  `cable_calibration_save`. Mode says GET on these, but the page does not
  say a GET of an action is harmless.
- **guarded** (set refuses without `DHS_PRISM_ALLOW_ACTIONS=1`):
  `system_reboot`, `system_poweroff`, `data_logger_db_new`, `fan_diag`,
  `eye_calibration_reset`, `eye_calibration_save`,
  `cable_calibration_reset`, `cable_calibration_save`, `serial_number`,
  `nomenclature`, `ip_mac_address`.

## Compliance events

Constants in `codec/reply.go`; `Disconnect` logs the summary line.

| Label | Fires when |
|---|---|
| `prism_reply_unwrapped` | a JSON answer has no top-level `object` |
| `prism_reply_not_json` | a 2xx answer is not JSON (absorbed as text on a string call, a failure elsewhere) |
| `prism_scalar_form_differs` | one number arrives in the form `DHS_PRISM_SCALAR` does not expect |
| `prism_reply_wrong_type` | the value is not of the call's datatype |
| `prism_error_in_2xx` | a 2xx answer holds a top-level `error` (a failure, never a value) |
| `prism_readback_differs` | the read-back is not the value written |

## Open questions, settle at the customer site

Each one has a reading in the code, and the runbook step that settles it.

| # | Question | Reading taken | Where to change it |
|---|---|---|---|
| 1 | Port. The page's text says 9000; its row links, and the origin the page was saved from, use 80. | 9000; `<host>:80` overrides | `DefaultPort` |
| 2 | Authentication. The table is silent. A comment in the page's script: calls with the `PASSWORD` option take `-H Authorization: Basic <password>`. Whether the password is sent as it stands or base64-encoded, and which calls need it, is not said. | header sent on every call when `DHS_PRISM_PASS` is set, value as it stands | `newREST` |
| 3 | TLS. The page shows `http://` only. | no TLS | `Connect` |
| 4 | Error shape. Undefined. | any non-2xx is a refusal, status and body start recorded; 401/403 are `ErrUnauthorized`; a 2xx with a top-level `error` is a failure | `exchange`, `DecodeReply` |
| 5 | Does a scalar GET use `object`? "Replies appear to wrap"; only objects are documented. | yes; if not, `prism_reply_unwrapped` fires and the value is kept | `DecodeReply` |
| 6 | Scalar form on the wire, `3` or `[3]`. Plural datatypes and the quantity examples point to an array; no ints example with one value exists. | array, both ways; `DHS_PRISM_SCALAR=bare` switches | `ScalarForm` |
| 7 | ints with symbolic options: name or number on the wire? The page gives names and no numbers. | the name as a JSON string on set; an integer is also accepted, because the datatype says ints and a read may answer one | `intItem` |
| 8 | POST body of a string call. | `{"object":"text"}` | `EncodeBody` |
| 9 | sysio (`video_input`): "specifying the respective index". | treated as ints | `EncodeBody` |
| 10 | What a POST answers. Undefined. | ignored, unless it holds a top-level `error`; truth comes from the read-back | `PostFailed` |
| 11 | How soon a POST reads back. Undefined. | at once, no invented settle; a lag shows as `prism_readback_differs` | `SetValue` |
| 12 | The page disagrees with itself: `ip_signal_status` and six `ip_ethernet_*_count` calls say "scope of IP1 or IP2", and their link uses `config0`. | the description; a scope outside the family is still passed to the instrument, so `ip_signal_status/config0` can be tried | `scopeOf` |
| 13 | Is a GET of the no-read calls harmless? | never sent | `noRead` in the tool |
| 14 | Does this catalogue match the firmware on site? The page is one instrument's. | compiled as is; `apiHelp.json` from the runbook settles it | re-run the tool |
| 15 | Answer size and rate. `eye_histogram_data` is raw data; the page gives no rate limit. | 16 MiB cap; walk one call at a time with no pause | `maxBody` |

## Timeouts

One answer's wait, never a whole-command limit. `get`, `set`, `info`:
`--timeout` for each exchange (`answers` in `consumer/plugin.go`). `walk`,
`watch`, `export`: the shared client's 5 s for each exchange,
`DHS_PRISM_ANSWER_WAIT` to change it. Five transport failures in a row
end a walk: the instrument is gone.

## What NOT to do

- Never GET a no-read call to "see what happens" on a customer's instrument.
- Never treat a POST's 2xx as applied: read it back.
- Never hand-edit `catalogue.tsv`.
- Never commit the page or its `_files` folder.
- Never put a customer address in a fixture.
