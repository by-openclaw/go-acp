# Lab provisioning — EVS Neuron + Riedel FusioN

Bring every device to its base setup and give every sender its multicast
groups. The base setup covers PTP, NTP main and backup, NMOS, network (DHCP
today, static in production), FEC and labels, plus per-channel SDI output
settings on the FusioN.

Edit the CSVs here, then run Ansible from the control node (dhs-debian). No
vendor tool is needed.

## Files

| File | What it holds | Who edits it |
|---|---|---|
| `site.csv` | plant-wide values: NTP main + backup, PTP domain, NMOS registry + backup, syslog, DNS | you |
| `devices.csv` | one row per device (see below) | you |
| `base-<type>.csv` | the base setup of one device type, written as a DM (see below) | you |
| `mcast-ranges.csv` | essence × plane → /16 and UDP port | you (plant plan) |
| `mcast-plan.csv` | every sender: RED group + port, BLUE group + port | generated by `provision-plan.yml` |
| `apply-report.csv` | every item of the last apply: before, after, status | generated, not committed |

Each `devices.csv` row holds:

- type, management IP and `planes` (`RED` or `RED+BLUE`);
- `channels` (FusioN: the receive channels in use);
- NMOS label and hostname;
- `ip_mode`, plus the static RED/BLUE address, netmask and gateway;
- FEC per plane and `mcast_apply`.

Device types: `neuron-convert-hybrid`, `neuron-bridge`, `neuron-shuffle`, `neuron-view`, `fusion6`.

### A base CSV is a DM

| Column | Meaning |
|---|---|
| `plane` | `RED` / `BLUE`: the row is skipped on a device that does not have that plane |
| `resource`, `select`, `field` | where the value lives. `select` picks a collection member (`name=Control Port Mac 1`, FusioN `channel={ch}`) |
| `value` | literal, or `{key}` from `site.csv` / `devices.csv`. An empty or unset value leaves the device value as it is |
| `type`, `format`, `enum`, `min`, `max` | the DM. A value outside them is refused before anything is sent |
| `source` | where the DM comes from: the device spec (`api.yml`, `openapi.yml`), our FusioN DM (`dm fusion6.json`), the write test, or "device read" where no spec is served yet (NeuronView) |

`{ch}` repeats a row for each channel in `channels`. The FusioN uses this for the SDI outputs of CH2/4/6/8.

Static addressing is in every file, even while `ip_mode` is DHCP. The static
values are stored now, and switching `ip_mode` to `Manual` makes them
active. The proposed static addresses sit outside the switch DHCP pool
(.50–.99).

## Multicast plan

| Essence | RED | BLUE (RED + 64) | Port |
|---|---|---|---|
| Video | 239.20.0.0/16 | 239.84.0.0/16 | 20000 |
| Audio | 239.30.0.0/16 | 239.94.0.0/16 | 30000 |
| ANC | 239.40.0.0/16 | 239.104.0.0/16 | 40000 |

- Each device gets its own block of /24s per essence: `block_<essence>` in `devices.csv`, sized to its sender count, using `.1`–`.254`.
- A sender keeps its group across runs, and a new device gets the next free block.
- A RED-only device gets no BLUE group.
- The FusioN is receive-only here (CH2/4/6/8), so it has no sender in the plan.
- NetBox IPAM takes this role later.

## Run (on dhs-debian, from `ansible/`)

```bash
ansible-playbook playbooks/provision-plan.yml                   # 1. read every sender, write mcast-plan.csv
ansible-playbook playbooks/provision-apply.yml --check          # 2. dry run: what would change, sends nothing
ansible-playbook playbooks/provision-apply.yml                  # 3. apply
ansible-playbook playbooks/provision-apply.yml                  # 4. again: 0 changes
```

To narrow a run: `-e what=base` (or `mcast`), `-e device=lab-fusion-01`,
`-e limit=4` (the first 4 senders per essence).

## How each type is written

| Type | API | Senders |
|---|---|---|
| CONVERT Hybrid, Bridge | `https://<ip>/api/v1`, PUT of the whole document | `io/ip/senders/{video,audio,data}/<uuid>`: `legs[0]` RED, `legs[1]` BLUE |
| Shuffle | `https://<ip>/api` (no `/v1`) | `io/ip/senders/audio/<uuid>`: `primaryLeg` RED, `secondaryLeg` BLUE |
| NeuronView | `https://<ip>/api/v1` for the base setup | NMOS IS-05 on `:3000`: PATCH `staged`, `activate_immediate` (its REST has no address fields yet) |
| FusioN6 | `http://<in-band ip>/emsfp/node/v1` | none provisioned (receive only) |

The same requests are in Postman, one collection per type, under "dhs
provisioning — …" in the BY-SYSTEMS Team Workspace.

## Before you apply in the lab

- Changing a sender's group cuts every receiver still on the old group, until
  that receiver is reconnected (IS-05, or from Cerebrum).
- `lab-shuffle-01` is `mcast_apply=no` until its licence lands (2026-10-02).
  Until then it answers every write with 400. It also has 1 544 enabled
  senders: addressing them all starts about 13 Mb/s per sender.
- The FusioN has no NTP object; its time comes from PTP only.
