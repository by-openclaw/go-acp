# Lab provisioning — EVS Neuron + Riedel FusioN

Bring every device to its base setup (PTP, NTP, NMOS, network, FEC, labels) and
give every sender its RED/BLUE multicast group. Edit the CSVs here, then run
Ansible from the control node (dhs-debian). No vendor tool needed.

## Files

| File | What it holds | Who edits it |
|---|---|---|
| `devices.csv` | one row per device: type, management IP, NMOS label, FEC per plane, `mcast_apply` | you |
| `mcast-ranges.csv` | essence × plane → /16 and UDP port | you (plant plan) |
| `base-<type>.csv` | base setup of one device type: `resource`, `field`, `value` | you |
| `mcast-plan.csv` | every sender with its RED/BLUE group | generated by `provision-plan.yml` |
| `apply-report.csv` | every item of the last apply: before, after, status | generated, not committed |

Types: `neuron-convert-hybrid`, `neuron-bridge`, `neuron-shuffle`, `neuron-view`, `fusion6`.
A `{column}` in a base value is taken from `devices.csv` (`{fec_red}`, `{nmos_label}`, …).
An empty value leaves the field as it is.

## Multicast plan

| Essence | RED | BLUE (RED + 64) | Port |
|---|---|---|---|
| Video | 239.20.0.0/16 | 239.84.0.0/16 | 20000 |
| Audio | 239.30.0.0/16 | 239.94.0.0/16 | 30000 |
| ANC | 239.40.0.0/16 | 239.104.0.0/16 | 40000 |

Each device gets its own block of /24s per essence (`block_<essence>` in
`devices.csv`, sized to its sender count, `.1`–`.254` used). A sender keeps its
group across runs; a new device gets the next free block. NetBox IPAM takes
this role later.

## Run (on dhs-debian, from `ansible/`)

```bash
ansible-playbook playbooks/provision-plan.yml                   # 1. read every sender, write mcast-plan.csv
ansible-playbook playbooks/provision-apply.yml --check          # 2. dry run: what would change, sends nothing
ansible-playbook playbooks/provision-apply.yml                  # 3. apply
ansible-playbook playbooks/provision-apply.yml                  # 4. again: 0 changes
```

Narrow it down: `-e what=base` (or `mcast`), `-e device=lab-fusion-01`,
`-e limit=4` (first 4 senders per essence).

## How each type is written

| Type | API | Senders |
|---|---|---|
| CONVERT Hybrid, Bridge | `https://<ip>/api/v1`, PUT of the whole document | `io/ip/senders/{video,audio,data}/<uuid>` `legs[0]` RED, `legs[1]` BLUE |
| Shuffle | `https://<ip>/api` (no `/v1`) | `io/ip/senders/audio/<uuid>` `primaryLeg` / `secondaryLeg` |
| NeuronView | `https://<ip>/api/v1` for base | NMOS IS-05 `:3000` — PATCH `staged`, `activate_immediate` (no address fields in its REST yet) |
| FusioN6 | `http://<in-band ip>/emsfp/node/v1` | `flows/<id>` per leg: `dst_ip_addr`, `dst_udp_port`, `dst_mac` (RFC 1112) |

The same requests, one collection per type, are in Postman (BY-SYSTEMS Team
Workspace, "dhs provisioning — …").

## Before you apply in the lab

- Changing a sender's group cuts every receiver still on the old group until it
  is reconnected (IS-05, or from Cerebrum).
- `lab-shuffle-01` is `mcast_apply=no`: it answers every write with 400 "licenses
  not loaded yet". It also has 1 544 enabled senders: addressing them all starts
  about 13 Mb/s per sender per leg.
